3. THE BIG WIN, AND HOW IT WAS FOUND
=============================================================================
Commit 5c6b692 — "Let exposed rock reach the screen by gating the ice light floor".

The summit rendered every face white however steep. Four fixes aimed at the
material chain each measured correct and changed nothing, because they were all
upstream of the fault. `textured_surface_lighting` was floored at
`biome_color(2u) * 0.65 * ice_light_floor` wherever `ice_share > 0`, and
`ice_share` came straight off the BAKED BIOME. On an all-ice summit that pinned
every pixel at ~0.52 linear while an honest rock face computes to
`albedo 0.065 * irradiance 0.53 = 0.035`. A 7x floor downstream of every
material decision. Gating it by the same `snow_slope_hold` the material uses:
lighting-stage rock/snow contrast 1.54x -> 5.64x, final 1.42x -> 2.31x, judges
2.9 -> 3.23, frame time unchanged.

**The technique that found it, after four cycles of failure: trace ONE SET OF
PIXELS through every stage.** Take pixels that are dark rock in the material
stage, then measure what those same pixels become at albedo, at lighting, at
final. The stage where contrast collapses is the culprit. Measuring each stage
in isolation hid this for hours. Debug modes exist for exactly this:
CATINGARDEN_DEBUG_MODE=albedo|lighting|aerial. I added slope/snowhold/basecolor/
tint/weathersnow/irradiance modes, used them, and stripped them again — re-add
what you need, they are cheap.

4. THE SECOND BIG WIN — ALTITUDE MUST BE SCALED (IAN'S INSIGHT)
=============================================================================
This planet's highest peak is 186,709m. Everest is 8,849m. Scale factor 21.10x.

  Earth                  altitude    here
  Everest                8,849m      186,709m   <- our old judging site, exactly
  Mont Blanc             4,808m      101,446m
  Jungfraujoch (Sphinx)  3,571m       75,346m
  Aletsch upper glacier  3,400m       71,738m
  Konkordiaplatz         2,800m       59,078m

The Aletsch photographs correspond to **59,000-75,000m here**, not 3-4km. I
wasted seven site searches hunting "3-4km alpine terrain" and got ocean, forest
and high lakes every time, because 3-4km on this planet is a scaled sea-level
swamp. Glaciers live at 13-31km+ (Earth-equivalent 600-1,500m hills). CONVERT
BEFORE CHOOSING ANY LOCATION.

The atmosphere scales too: RAYLEIGH_SCALE_HEIGHT_METERS is 72,000m against
Earth's ~8,500m, so 79km carries ~1/e of sea-level density overhead and has real
skylight. At the old 186km summit there was essentially none, which is why round
10's judges asked for shadow fill the location could never physically supply.

Current judging site (committed, aace6e3): 79,247m, lat 48.6, Earth-equivalent
3,756m, 96.9% glaciated. Clearance measures 100.47m, all assertions pass.

6. WHERE I STOPPED — GLACIER STRUCTURE (UNCOMMITTED, WORKING, NOT VISIBLE)
=============================================================================
Round 11 judges unanimously named what is missing: crevasses, seracs, medial
moraines, rock strata. These are absent FEATURES, not tuning problems. You
cannot tune a constant into a moraine.

Implemented (uncommitted, all tests green, 582 passing):
 - BiomeId::GlacialMoraine = 10, BiomeId::CrevasseField = 11 in coretypes.
   ALL is now [Self; 12]; name(), color() updated; TryFrom derives from ALL.
 - Baker `classify_biomes`: on ALTITUDE ice only (never polar sheets), moraine
   where flow_accumulation exceeds a quantile of this bake's own ice, crevasse
   where slope exceeds one. Thresholds are QUANTILES not constants, each with an
   absolute floor beneath it.
 - Area-weighted biome census printed by every bake (crates/baker/src/lib.rs).
 - Shader: palette cases 10u/11u, terrain_material_is_snow includes 11u,
   biome_blend_snow_share includes 11u, material weights make 10u rock-dominant
   with no snow and 11u snow at 0.82.

THE BLOCKER, measured: thin features are decimated by export resampling.

                working grid (preview)    exported L4 tiles
  moraine       7,356 px = 0.088%         368 cells = 0.0014%   (~60x loss)
  crevasse      97,230 px = 1.16%         5,642 cells = 0.022%  (~50x loss)

The classifier works — the preview proves it, and the crop looks like real
drainage threading through ice. But the export resamples the 4096x2048
equirectangular working grid onto cube-face tiles and one-cell-wide features
fall between samples. Only 417 of 1,536 L4 tiles retain any structure, and the
judging site's tile (py/l04/x000005_y000001) has NONE. Round 12 frames are
byte-identical to round 11 for an honest reason: there is nothing there to draw.

My recommendation: DILATE the structure in the working grid before export (grow
moraine/crevasse by a cell or two) so it survives resampling. At ~3km sample
spacing a real medial moraine is far below grid resolution anyway, so this is
already a stylised representation. Widening the thresholds instead makes the
features more COMMON rather than THICKER, so thin threads would still be lost.

Three bakes have been spent on this. Each takes a few minutes, not hours.

7. TRAPS THAT COST ME MOST OF TWO DAYS — PLEASE READ
=============================================================================
Every one of these is the same shape: AN ARTEFACT THAT LOOKS CURRENT BUT WAS
PRODUCED BY DIFFERENT CODE. Verify the artefact contains your change (mtime, or
`strings <binary> | grep '<a comment you just wrote>'`) BEFORE trusting a run.
Identical output across two runs that should differ means staleness until
disproved — not "the change had no effect".

 1. Scenarios are include_str!'d. Edit the JSON, run without `cargo build`, and
    you replay the OLD scenario silently.
 2. WGSL is validated at pipeline creation, NOT at cargo build. A clean build
    says nothing about the shader. Run
    `cargo test -p catinthegarden-app --bin catinthegarden-app \
     planet_shader_validates_with_filtered_runtime_detail_noise`.
 3. `cargo test -p X --lib` builds the LIB TEST target, not the CLI binary. Two
    full bakes ran the pre-edit baker and produced byte-identical output; I
    nearly concluded my classifier change did nothing.
 4. A run manifest records the repository HEAD, not the binary (see §5).
 5. NEVER pipe a gated command into tail/head/grep. A pipeline returns the LAST
    command's status, so `cargo test ... | tail && git commit` commits on a
    FAILING test. It did. Use `set -o pipefail` or redirect to a file.
 6. Scenario replays need xvfb. On DISPLAY=:0 they stall silently, GPU at 0%,
    and write no captures.
 7. The preview PNGs (assets/outmaps/test-planet/previews/) are ~10km averages
    and under-report peaks by ~12km. My offline L4 tile reads were also
    misaligned. ONLY the renderer's own `camera_surface_height_meters` has ever
    been right about heights. Put a control site of KNOWN height in any probe
    scenario and verify the method before trusting new numbers.
 8. docs/HANDOFF.md's recorded bake command is WRONG for this planet. It bakes
    from ETOPO; this planet's manifest says `procedural continent/mountain
    generator`. Copying it would silently produce a different world and
    invalidate every judged round. The correct command is in §8.
 9. VERIFY BY EYE, NOT ONLY BY HISTOGRAM. Eight candidate sites and four
    material fixes passed on numbers and failed on the picture. A plausible
    percentage is not evidence. Open the frames.
10. Do not spend a judging round on a change that is a no-op to the eye. Round 9
    was staged and never judged for exactly this reason; the series runs 8 -> 10
    -> 11 with that gap documented.
