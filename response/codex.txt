Yes, but “LOD level 1 globally with no exceptions” needs a precise scope.

For rendered quadtree geometry, the current system can be hard-capped at L1. Today normal mode starts at L2 and can refine to L18; flat-triangle mode explicitly fixes L7. A true L1 cap would override both policies and prevent any chunk from rendering above L1.

It would not automatically stop higher-resolution baked tiles or near-field/ray data from being streamed, because those are separate from rendered mesh LOD. If “no exceptions” includes data streaming too, those paths would also need to be capped/disabled.

Expected result: six cube faces × four L1 chunks = 24 coarse chunks (before culling), with very low triangle count but continent-scale facets and almost no mountain detail. Existing L2+ assumptions/tests would need updating. No code changed.
