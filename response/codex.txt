I’ve checked the current code. **It still exists, but it’s an alternative terrain renderer—not an optimisation applied to the normal view.**

- **Normal rendering is rasterised terrain meshes.** That’s what your latest screenshots and the recent road/ocean work use. The foveated ray pass isn’t running in that mode.
- **F5 switches to the foveated ray renderer.** It ray-marches the planet’s height field into a warped image, then reconstructs the screen image and depth. Its intermediate image is 75% of the viewport width and height—about 56% as many pixels—with sampling concentrated around the focus.
- **The focus follows travel direction**, easing back to the centre when stationary. It isn’t eye-tracked.
- **It has been maintained:** it supports a streamed, higher-detail terrain window near the camera, alongside its coarse whole-planet data. However, it is not a fully equivalent replacement for the current raster path; recent features and fixes have not all been validated there.
- **It still costs startup time and GPU memory in raster mode.** We initialise it regardless, partly because its whole-planet height textures also supply the raster terrain’s cast shadows. That does not mean the foveated drawing pass runs every frame.

So: **a working alternative/experimental path, plus shared shadow data—not currently the mechanism keeping the main renderer’s FPS up.** It also doesn’t automatically foveate roads, trees and the rest of the scene.
